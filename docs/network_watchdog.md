# Network watchdog: uplinks and field links

The watchdog monitors only internet uplinks. It never probes a field interface against an internet target or changes its route metric. The operational heartbeat and Modbus poller do not depend on a successful watchdog probe.

Set `features.network_watchdog.interface_roles` in `/etc/novena-gateway/config.json` when the installer knows the layout. Supported values are `uplink` and `field`, keyed by the configured Linux interface name. An omitted role is inferred from the kernel's active IPv4 default routes: an interface with a default route is an uplink; one without is a field link. For example, a CM4 connected directly to a Modbus simulator has `"interface_roles": {"eth0": "field", "wlan0": "uplink"}`. A site using Ethernet for internet can set `"eth0": "uplink"` and leave Wi-Fi as another uplink. An explicitly declared uplink without an active default route is reported as `no_default_route` and cannot be selected for failover.

`health_targets` is a nonempty list of IP addresses or hostnames. The default remains `8.8.8.8`. A private or ICMP-restricted site should configure reachable, stable targets that prove its intended upstream path. A failed target is reported as `probe_failed`, separately from `physical_up`; it does not mean the equipment link failed. Set `mode` to `diagnostic` during site qualification to observe decisions without route changes. `auto` enables temporary route changes only when the privileged helper is installed.

The watchdog publishes `interface_diagnostics` in the operational attribute heartbeat. Each interface includes `role`, `role_reason`, `physical_up`, `default_route`, `probe_ok`, and `status`. `active_interface` identifies the selected uplink, not an equipment connection. If a NetworkManager profile is missing or unmanaged, the watchdog logs the skipped action and does not claim a failover. The helper checks the active profile UUID and applies a temporary device metric without reactivating the link or editing the saved profile. It restores recorded metrics when switching away or stopping, provided the same profile is still active. A process crash can leave a temporary metric until NetworkManager reapplies the profile; inspect `ip -4 route` and reconnect the profile during recovery.

Qualification needs both layouts: field Ethernet + Wi-Fi uplink, and Ethernet uplink with a backup. Record `ip -4 route`, `nmcli -g GENERAL.CON-UUID device show <interface>`, Gateway attributes, broker heartbeats, Modbus polling, and route metrics before and after controlled upstream interruption. Software tests alone do not qualify automatic failover for customers.
